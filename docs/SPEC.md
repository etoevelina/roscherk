# «Росчерк» — головоломки одной линией. Спецификация v2

Версия 2 учитывает ревью трёх независимых критиков (геймдизайн, iOS UX, инженерия).
Это единственный источник истины для всех, кто пишет код. Если код и спека расходятся —
исправляется код, либо спека правится явно с пометкой в коммите.

## 0. Контекст и ключевые решения
- Платформа: **веб-приложение для iPhone Safari** («На экран Домой», офлайн). Xcode на машине
  нет; нативная установка без платного аккаунта разработчика живёт 7 дней. Веб-апп живёт вечно.
- Стек: HTML + Canvas 2D + ванильный JS (ES-модули), сборка esbuild в **один файл**
  `dist/index.html` + `manifest.webmanifest`, `sw.js`, `icon-180.png`, `icon-512.png`.
  Никаких фреймворков, внешних шрифтов, CDN.
- Язык UI: русский. Контракт строк `{ru, en}` сохраняется, в v1 наполняется только `ru`,
  переключатель языка скрыт.
- Уровни генерируются **офлайн** (Node, детерминированно от seed) и вшиваются в сборку.
  В рантайме генераторов нет. Все лимиты в генераторах/солверах — **по числу узлов поиска**,
  не по времени (иначе результат зависит от машины).
- Публикация: `dist/` на любом HTTPS-хостинге статики (основной вариант — GitHub Pages из
  папки `dist`, запасной — страница-артефакт). Все пути в сборке относительные (`./`), чтобы
  работать из подпапки. Проверка на реальном iPhone — только по опубликованному URL;
  `npm run dev` — отладка на Mac. Регистрация SW и манифест — под try/catch, чтобы `file://`
  тоже открывался (без офлайна и установки).

## 1. Что это
Мобильная логическая игра, в которой каждое решение **рисуется пальцем одной непрерывной
линией**. Три режима с общей оболочкой, 100 уровней кампании на режим + пулы для
«Бесконечности» и «Ежедневной», прогресс и незавершённая партия сохраняются на устройстве.
Четвёртый режим — «Слова» (§2.5): английский акростих по темам, 100 уровней кампании, для
прокачки английского. Пятый — «Карандаш» (§2.6): физические головоломки, где нарисованное
становится твёрдым: довести шарик до цели, защитить мёд от роя.

Цель продукта — «зависнуть»: главы 1–2 — 20–60 с на уровень, главы 3–4 — 1–3 мин, глава 5 —
до 5 мин. Мгновенный отклик линии под пальцем, честные подсказки, приятная победа, «Дальше».

## 2. Общие правила для всех режимов

### 2.0 Сложность, тривиальность, кривая
- Солвер каждого режима возвращает `difficulty` — число **настоящих развилок**:
  - zip/flow: узлы полного обхода, где после пропагации принудительных ходов ≥ 2 легальных
    продолжения, и ложная ветвь живёт ≥ 3 шагов до отсечения;
  - stroke: число «ловушек» — позиций эталонного решения, из которых есть непройденное ребро,
    ведущее в тупик (мост, пройденный преждевременно).
- Генератор делает ≥ 2× кандидатов на главу, отбрасывает уровни ниже порога тривиальности
  (zip: главы 1–2 ≥ 1, главы 3+ ≥ 3; flow: ≥ 2 с главы 2; stroke: ≥ 2 с 10-го уровня) и
  выбирает уровни главы так, чтобы `difficulty` **не убывал**, а соседние отличались не более
  чем в 2 раза (иначе генерирует ещё кандидатов). Пул «Бесконечности» также помечен `chapter`.
- У каждого уровня поля: `id` (8 hex — sha1 канонического JSON содержимого без служебных полей),
  `seed`, `chapter` (1–5), `difficulty`, `tip` (опционально `{ru}`), для flow — `unique: bool`.
  Прогресс хранится **по `id`**. Кампания и пулы после релиза — append-only: замена уровня =
  новый id. Seed уровня = hash(masterSeed, mode, kind, index): перегенерация одного уровня или
  режима не меняет остальные.

### 2.1 Попытка, звезда, подсказка, тупик
- **Попытка** начинается при открытии уровня (из списка, «Повторить», «Дальше») и заканчивается
  победой. `reset` новую попытку не начинает и `hintUsed` не сбрасывает.
- **Звезда** — за попытку без подсказок (flow: дополнительно «ходов = числу потоков»,
  см. 3.2). Звезда засчитывается при любом последующем перепрохождении.
- **Подсказка** — по второму тапу в течение 2 с (первый показывает «Подсказка? Звезда не
  засчитается»). Семантика по режимам — в разделах ниже. Подсказка рисуется режимом из
  `state.hint = {…, until}`; через ~2.5 с гаснет.
- **Сброс** мгновенный, но 5 с висит тост «Отменить сброс» (= обычный undo по снимку).
- **Undo** реализует оболочка стеком снимков `serialize(state)` глубиной ≤ 50: снимок
  делается перед каждым росчерком (down…up, изменившим состояние), перед `reset` и перед
  `hint`. Undo = `create(levelData, snapshot)`. Внутри росчерка откат — возврат пальцем.
- **Пропустить**: после 3 сбросов или 90 с без изменения состояния в нижней панели появляется
  «Пропустить» — уровень остаётся без галочки, следующий открывается.
- **Тупик stroke** (бесплатно, без потери звезды): если из текущей точки нет непройденных
  отрезков, а отрезки остались — тост «Тупик. Попробуй другую точку старта»; если выбор старта
  не важен (цикл без стрелок или фиксированный старт; событие `deadend` несёт
  `startMatters:false`) — «Тупик. Этот отрезок надо было пройти позже». На втором тупике за
  попытку нечётные точки пульсируют; счётчик тупиков — статистика попытки: undo его не
  откатывает (оболочка передаёт режиму снимок с максимумом из снимка и текущего значения).
  Так же undo не откатывает статистику попытки «Слов» (§2.5): число подсказок, вводы и ошибки
  (точность); `hintUsed`, раз поставленный, остаётся (`ATTEMPT_STATS` в `game.js`).

### 2.2 «Маршрут» (`zip`) — одна дорожка через все клетки
Сетка n×n. В клетках стоят числа 1…K. Нарисовать **одну** дорожку от 1 до K, проходящую через
**каждую** клетку ровно один раз, посещая числа **строго по порядку**. Между некоторыми
клетками есть **стены** (толстые линии). Ходы только по вертикали/горизонтали.

**Управление.** Палец на клетку 1 (если дорожка пуста) или на любую клетку дорожки — ведём;
дорожка растёт на соседнюю клетку под пальцем. Возврат пальцем на уже пройденную клетку
**укорачивает** дорожку до неё (только при движении, не на `pointerdown`). Отпустили — дорожка
остаётся, продолжить можно с её конца (касание любой клетки дорожки, затем движение).
Шаг в клетку с числом, большим следующего ожидаемого, **отклоняется** (событие `reject`:
тряска клетки, звук отказа, клетка не добавляется); следующее ожидаемое число мягко пульсирует
на поле и показано в шапке («следующая: 4»). Клетка K **терминальна**: из неё дорожка не
растёт; вход в K при незакрытых клетках отклоняется с `{kind:'reject', reason:'early-finish',
remaining:N}` → тост «Осталось клеток: N». Шаг через стену — `reject` со вспышкой стены.
**Победа** = все клетки закрыты и последняя клетка дорожки — K. Инвариант: полностью закрытое
поле всегда означает победу. На победе — «Возвратов: N» (число укороченных клеток, без штрафа).

**Кривая** (100 уровней кампании + пул 150 + daily 40):
- Глава 1: уровни 1–6 → 4×4, чисел 3–5, без стен.
- Глава 2: 7–25 → 5×5, чисел 4–6, стены с 15-го.
- Глава 3: 26–45 → 6×6, чисел 4–7, стены.
- Глава 4: 46–70 → 7×7, чисел 4–8, стены.
- Глава 5: 71–100 → 8×8, чисел 5–9, стены.
Стен ≤ n на уровень (0 в главе 1); стена не может оставить клетке ≤ 1 свободного соседа
(кроме клеток 1 и K). Верхний предел контрольных точек — верх диапазона главы + 1; при
превышении после ремонта затравка отвергается. В главах 4–5 чередуются профили «много чисел,
0–2 стены» и «мало чисел, стены до лимита»; профиль задаёт чётность `levelIndex`: чётный —
«много чисел» (жадное удаление точек не опускается ниже `marksMax − 1`), нечётный — «мало
чисел, стены до лимита» (половина стен ставится сразу, ремонт — сначала стенами). **Отклонение
для главы 5 (8×8)**: профиль «много чисел» ослаблен до **0–3 стен и до 12 чисел**
(`CH5.profileWalls = 3`, `CH5.profileMarksCap = 12` в `zip.gen.js`) — при строгих ≤ 2 стен /
≤ 10 чисел уникальная затравка выпадает ~1 % и генерация занимает десятки секунд на уровень
(измерено на masterSeed 20260101). Позиционные правила («стены с 15-го», чередование профилей)
привязаны к слоту `levelIndex` через `profile()` (§5.2, §5.5), поэтому выполняются в данных
поставки, а не только в генераторе. Каждый уровень имеет **ровно одно решение**.

**Генерация** (`src/modes/zip.gen.js`):
1. Гамильтонов путь: backbite (Mansfield) от «змейки», ≥ 100·N ходов (N = n²), конец пути для
   шага выбирается случайно. Пути, где доля клеток в прямых отрезках длины ≥ n−1 **рёбер**
   (т. е. ≥ n клеток — целая строка или столбец) превышает 40 %, отвергаются
   (`straightFraction(path, n, n)`).
2. Контрольные точки: 1 — начало, K — конец, промежуточные — равномерно с джиттером до
   целевого числа.
3. Стены — между ортогональными соседями, НЕ идущими подряд в пути (решение сохраняется),
   с учётом лимитов выше.
4. Солвер (`zip.solve.js`) при ремонте отдаёт **выборку до 256 альтернативных решений** за
   вызов. Ремонт неуникальности: контрольная точка ставится в клетку, которая убивает больше
   всего альтернатив выборки (при равенстве — ближе к клетке первого расхождения); стена — ребро
   вне пути решения, которым пользуется больше всего альтернатив. В профиле «много чисел» стена
   ставится только если точка не помогла; в профиле «мало чисел» — стены сначала, пока лимит не
   исчерпан. Между вызовами солвера выборка перепроверяется `validate()` (одна правка убивает
   сразу много альтернатив). Затем — жадное удаление контрольных точек при сохранении
   уникальности (в профиле «много чисел» — не ниже `marksMax − 1`). При исчерпании лимитов
   (стен, точек, вызовов/узлов солвера) — новая затравка.

**Солвер** (`zip.solve.js`): DFS с корректными (sound) отсечениями, не способными отрезать
решение: порядок чисел; связность непосещённых клеток по графу со стенами; ≤ 1 непосещённая
клетка степени 1 и это цель; паритет шахматной раскраски (среди R оставшихся клеток цвета,
противоположного голове, должно быть ⌈R/2⌉, цвета головы — ⌊R/2⌋, цвет цели согласован);
пропагация принудительных ходов (непосещённая клетка с ровно двумя свободными соседями
фиксирует оба ребра; сосед головы степени 1 — следующий ход). Поле — `Uint8Array`, без BigInt.
Лимит ≤ 2·10⁶ узлов на вызов, ≤ 10 вызовов на уровень. Возвращает `{solutions (≤2), nodes,
difficulty, complete}`.

**Подсказка**: если дорожка — префикс решения → подсветить следующие 3 клетки решения;
иначе — подсветить первую расходящуюся клетку и показать кнопку «Укоротить до неё».

### 2.3 «Потоки» (`flow`) — соедини пары, заполни поле
Сетка n×n, пары цветных точек. Соединить каждую пару дорожкой своего цвета, дорожки не
пересекаются, **все клетки** заполнены. Ходы по вертикали/горизонтали.

**Управление** (как Flow Free). Путь потока хранится упорядоченно от точки, с которой его
начали рисовать. `pointerdown` на любой из двух точек цвета начинает путь заново от этой точки
(старый путь стирается); `pointerdown` на клетке своего пути укорачивает до неё, **когда палец
покидает клетку касания** (первый `move` в другую клетку; дрожание в 1–2 px внутри клетки при
случайном тапе ничего не меняет); `pointerdown` на пустой клетке/чужой дорожке — ничего. Проведение по чужой дорожке
**обрезает** её: у чужого потока остаётся префикс до клетки касания (не включая её); событие
`cut` (вспышка чужой дорожки). Возврат на свою клетку укорачивает. Повторный вход в свою первую
точку отклоняется. Путь завершён, когда дошёл до второй точки своего цвета; дальше не растёт
(событие `complete` — отдельный звук). **Ход** = росчерк (down…up), изменивший поле:
сравнивается поле до росчерка и после — росчерк, вернувший дорожки в исходный вид, ходом не
считается; смена точки старта пустой дорожки — не ход; при победе внутри `move` ход
засчитывается сразу (до `up`). `reset` очищает поле и счётчик ходов (он описывает текущее поле,
«ходов N» в нижней панели), но не `hintUsed`; undo восстанавливает ходы из снимка.
Победа — все пары соединены и нет пустых клеток (принимается **любое** корректное заполнение).
В нижней панели одной строкой: «ходов 5 · 83 %» — процент считается по клеткам дорожек длины ≥ 2
(одиночные точки старта не входят: в начале уровня 0 %, при победе 100 %).

**Звезда**: без подсказок И ходов = числу потоков («Идеально»). На оверлее «Ходов 7 / 6» и
кнопка «Повторить за звездой», если звезда не получена.

**Кривая** (100 + пул 150 + daily 40):
- Глава 1: 1–12 → 5×5, 4–6 потоков.  Глава 2: 13–35 → 6×6, 4–6.  Глава 3: 36–60 → 7×7, 5–8.
- Глава 4: 61–85 → 8×8, 6–10.  Глава 5: 86–100 → 9×9, 9–12.
Уникальность: n ≤ 8 **обязательна**; 9×9 — best effort при лимите узлов, результат пишется
в `unique:false` и учитывается подсказкой.

**Отбор по качеству**: нет потоков длины 2; не более трети прямых; ≥ 2 потока с ≥ 2
поворотами; отвергать уровни, где у ≥ 50 % точек есть смежная точка другого потока. Пары точек
на разрезе пути (конец сегмента и начало следующего) смежны по построению и в подсчёте не
участвуют — считаются только иные соседства.

**Генерация** (`flow.gen.js`): гамильтонов путь (backbite, как в zip) → разрезание на F
сегментов длиной ≥ 3 → концы = точки. При 2 решениях — разрезать поток в клетке первого
расхождения (F+1, если F ≤ Fmax главы), иначе другие точки разреза того же пути (до 20
попыток), только потом новый путь.

**Солвер** (`flow.solve.js`): DFS; поток для расширения — детерминированная функция состояния
(незавершённый поток с наименьшим числом вариантов, при равенстве — с меньшим индексом), чтобы
каждое заполнение считалось ровно один раз; обе точки потока — «головы»; единственный легальный
шаг головы делается без ветвления. Отсечения только корректные: у пустой клетки ≥ 2 свободных
соседа или она сосед головы; головы каждого незавершённого потока связаны через пустые клетки
(BFS); каждая пустая область касается незавершённого потока. Эвристика «нет 2×2 одного цвета»
**запрещена** (режет легитимные заполнения). Лимит ≤ 5·10⁶ узлов на вызов.

**Подсказка**: раскрыть один незавершённый поток целиком (последний тронутый, иначе самый
короткий по решению); мешающие чужие дорожки обрезаются по правилу обрезки.

**Палитра**: две палитры (тёмная/светлая тема) с одинаковым порядком 12 оттенков; каждый цвет —
контраст ≥ 3:1 к фону своей темы, соседние по индексу различимы в обеих темах. Настройка
«Номера на точках» (по умолчанию выкл.) рисует индекс потока на обеих точках пары.

### 2.4 «Один штрих» (`stroke`) — обведи фигуру, не отрывая пальца
Фигура из точек и отрезков. Провести по **каждому** отрезку ровно один раз одним
непрерывным росчерком (эйлеров путь). Точки можно проходить многократно. Модификаторы:
**стрелки** (отрезок проходится только в направлении стрелки), **фиксированный старт**
(отмеченная точка), **замкнутый росчерк** (`closed: true` — закончить в начальной точке).

**Управление.** Палец на любую точку (или на отмеченную при фиксированном старте) — начало.
Узел захватывается в радиусе max(22pt, 0.35·шага решётки); отрезок движения указателя «прошёл
через узел», если расстояние от узла до отрезка меньше этого радиуса; узлы обрабатываются в
порядке прохождения. Переход к соседней точке по непройденному отрезку закрашивает его
(`step`). Возврат на предыдущую точку отменяет последний отрезок. Попытка пройти по пройденному
отрезку, против стрелки или в несмежную точку — `reject` (вспышка отрезка, тряска). Отпустили —
путь остаётся, продолжить можно с конца. Победа — все отрезки закрашены (и при `closed` —
последний узел = первому).

**Кривая** (100 + пул 150 + daily 40): решётка точек 3×3 → 4×4 → 5×5 → 6×5; число отрезков
6 → 32. Главы: 1–10 (3×3, 6–9 рёбер), 11–30 (4×4, 9–14), 31–55 (4×4/5×4, 13–20), 56–80 (5×5,
18–26), 81–100 (6×5, 24–32). С 10-го уровня ≥ 3 узла степени ≥ 3; с 20-го edges/nodes ≥ 1.3.
Стрелки с 25-го (1–2 на фигуру, к 70-му — до половины отрезков). Фиксированный старт — каждый
5-й уровень с 15-го. `closed: true` — каждый 4-й уровень с 40-го. Ранние уровни чаще цикл
(старт где угодно), поздние — две нечётные точки (нужно найти старт).

**Генерация** (`stroke.gen.js`): решётка точек w×h; кандидаты-рёбра — соседи по
горизонтали/вертикали и диагонали единичной клетки (в одной клетке только одна диагональ).
Случайный маршрут без повтора рёбер длины L — он и есть фигура и эталонное решение; для цикла
после L−k шагов маршрут возвращается к старту кратчайшим путём по свободным рёбрам, иначе
отвергается; застревание до длины L — рестарт. Фильтры: узлов ≥ 5; хвост (цепочка ≥ 3 вершин
степени 2, оканчивающаяся вершиной степени 1) — отвергать; плотность и степени — по кривой.
Стрелки ставятся по направлению эталонного маршрута. Для отображения — детерминированный
джиттер узлов ±15 % шага (от seed) с проверкой, что рёбра после сдвига не пересекаются (иначе
джиттер делится пополам) — координаты узлов в данных уже с джиттером, в единицах решётки.

**Солвер** (`stroke.solve.js`): для неориентированного остатка существование завершения из
вершины v — O(E) по чётности степеней и связности; маршрут — Хирхольцер. Для смешанного графа
(стрелки) — DFS с лимитом узлов (≤ 2·10⁵). `difficulty` — число ловушек по 2.0.

**Подсказка**: найти самый длинный префикс текущего пути, из которого существует завершение.
Если префикс = весь путь — подсветить следующее ребро любого завершения; иначе — вершину, до
которой нужно откатиться; если префикс пуст — любую допустимую стартовую вершину. При
превышении лимита узлов подсказка не показывается и звезда не снимается.

### 2.5 «Слова» (`words`) — английский акростих с номерами букв (как Crostic)
Четвёртый режим, добавлен 2026-10-15 по просьбе: «кроссворды на английском по разным темам, как у
Crostic, интересные слова, чтобы прокачивать английский». Дизайн — **дизайн-система Lumin**
(`~/Downloads/lumin-word-design-system/index.html`): механика, токены, экраны, движение и
доступность берутся оттуда. Это **не** рисование линией: режим живёт в той же оболочке (кампания,
прогресс, undo, звезда, победа), но рисуется DOM-разметкой (кнопки с aria-label для VoiceOver,
системный шрифт, Dynamic Type) и вводит буквы с экранной клавиатуры.

**Механика (Lumin «One number, one letter»).** Уровень — английская цитата (публичное достояние
или пословица) и 4–10 слов-ответов с английскими определениями. У каждой буквы алфавита,
встречающейся в цитате или ответах, — свой номер (1…K, перемешаны). Клетки цитаты и клетки
ответов подписаны номерами; буква, введённая в любую клетку, ставится **во все клетки с этим
номером** (в цитате и во всех ответах). Буквы ответов покрывают все буквы цитаты, кроме 1–2
**открытых** букв (даны с начала). **Победа** — все клетки цитаты верны. Слова-ответы — главная
учебная часть: определение по-английски, перевод — после отгадки или по подсказке, все слова с
переводами — на экране победы.
- **Ошибки локальны** (Lumin): неверная буква на ~0,4 с подсвечивается цветом ошибки с
  перечёркиванием (не только цветом), лёгкая вибрация, без тряски и звука отказа; буква остаётся,
  её можно исправить без штрафа. Счётчик точности: верных вводов / всех вводов.
- **Слово отгадано** (все его буквы верны) — фишка ответа становится шалфейной с галочкой, тост с
  переводом «rinse — полоскать», звук `complete`, средняя вибрация.
- Все клетки цитаты заполнены, но есть ошибки → тост «Есть ошибки — проверь буквы» (без штрафа).

**Экран** (Lumin «Puzzle»: цитата над ответом, клавиатура не перекрывает ответ): шапка цвета
фона (назад, «Тема · 3/5», кнопка подсказки), карточка цитаты (плитки 31×39 → уменьшаются, чтобы
цитата поместилась; слова не разрываются; номер — мелко внизу плитки; знаки препинания — без
плиток), фишки ответов A…J, блок ответа (круг с буквой ответа, определение, «adj. · 7 букв»,
перевод, клетки-подчёркивания с номерами, ‹ ›), строка «Отменить · Сбросить · слов 3/7», клавиатура.
Выделение — лавандовая заливка **и** рамка (не только цвет); клетки с тем же номером — светлая
лаванда в обеих зонах; решённые буквы — шалфей.

**Ввод.** Тап по клетке цитаты/ответа — выделить (зона «цитата»/«ответ»); тап по фишке —
выбрать ответ (курсор на первую пустую клетку); ‹ › — соседний ответ. Открытые буквы не
выделяются. Буква: ставится по номеру во все клетки, курсор — к следующей пустой клетке зоны
(в ответе — по слову; слово заполнено → первая пустая клетка следующего незаполненного ответа).
⌫ стирает номер выделенной клетки, а если он пуст — переходит к предыдущей клетке и стирает её.
С физической клавиатуры — буквы, Backspace, ← →, Enter/Tab = следующий ответ. Каждое изменение
букв — шаг undo; смена выделения — не шаг.

**Подсказки** (Lumin «Hints»: нижняя шторка, эффект виден до выбора, без «языка стыда»; любая
снимает звезду, о чём шторка пишет, пока звезда ещё возможна): «Открыть букву» (номер выделенной
клетки, иначе первый неверный/пустой в ответе — во всех клетках), «Проверить ответ» (неверные
буквы текущего ответа помечаются до исправления), «Показать перевод» (перевод определения).
Всё верно — подсказок нет.

**Победа** (Lumin «Level complete»: спокойно, без конфетти, разрешается в покой ≤ 1 с): полный
экран — галочка в шалфейном круге (одно восходящее движение), «Цитата собрана», цитата по центру,
автор, перевод, статистика «Время · Подсказки · Точность», список слов уровня с переводами,
«Дальше» (основная, чернильная) и «Повторить».

**Кампания** (Lumin «Word packs» + «Level map»): 20 тем × 5 уровней = 100 — «Дом и быт», «Еда и
кухня», «Путешествия», …, «Язык и общение». Экран уровней — карточки тем (абстрактная
градиентная форма, название, «5 уровней · 2 пройдено») с дорожкой из 5 узлов: пройден — чернильная
заливка с галочкой, текущий — лавандовое кольцо, закрыт — приглушён. Окно из 3 открытых уровней
считается **в каждой теме отдельно** (`mode.openByChapter`): тему можно начать когда угодно.
Внутри темы уровни идут по длине цитаты. Каждое слово встречается в кампании один раз (и в одной
теме — проверяет `check-theme`). Режим только в кампании (`mode.campaignOnly`): в «Ежедневную» и
«Бесконечность» не входит, чередование Ежедневной (zip → flow → stroke) не меняется; экран
«Кампания пройдена» для него зовёт к списку тем. «Тема пройдена» — только когда пройдены все её
уровни; «Дальше» ведёт к следующему открытому непройденному уровню этой темы, иначе любой темы,
иначе к списку тем; «Кампания пройдена» — когда пройдены все 100. При первом входе — знакомство
из трёх карточек (отгадывай → связывай → открывай), один раз (`settings.introSeen`); таймер уровня
в это время стоит.

**Токены** (Lumin; светлая тема — как в дизайн-системе, тёмная — производная с теми же оттенками):
ink #111311, canvas #F3F4EF, paper #FBFCF9, sage #B9C8B3 / #DCE5D8, lavender #C9C4DF / #EBE8F4,
line ink/10 %, danger #9A5E5E; ради WCAG AA затемнены muted #6E746F → #5F655F и success #5F795E →
#56705A, добавлены номера клеток #5A605B, лавандовый текст #6F6890 и кольцо выделения #8F88A7;
радиусы 8/12/20/32; движение 120 мс (нажатие), 220 мс (распространение буквы), 360 мс (шторка),
700 мс (финал); при Reduce Motion — без перемещений. Кнопки панели (фишки, ‹ ›, нижняя строка) —
44 pt; клетки цитаты меньше (21–31 px), как в Lumin. Под статус-баром светлого экрана — тёмная
полоса высотой safe-area (§4.1). Иконка приложения — `assets/icon.png` (мастер 1254×1254, без
прозрачности; он же иконка App Store).

**Контент** (офлайн, `tools/words/`): `themes/<slug>.json` — цитаты (`q`, `a`, `src`, `ru`) и
95+ слов (`w` 4–11 букв, `p` n/v/adj/adv, `c` — английское определение без самого слова и его
корня, `ru` — перевод); формат проверяет `tools/words/check-theme.mjs`. Составлен авторами-агентами
и проверен агентами-критиками (точность определений и переводов, атрибуция цитат по источникам).
Определение не содержит ни самого ответа, ни его корня, ни целой его части (BEFRIEND ← «friend»).
`tools/words.mjs` (`npm run words`): для каждой цитаты темы — рандомизированный жадный подбор
ещё не использованных в кампании слов темы, которые **покрывают все буквы цитаты** (минус 1–2
открытые), с максимумом «полезных» букв (буквы ответа, встречающиеся в цитате) и 4–10 словами;
ответ не совпадает со словом цитаты; ответы одного уровня не «пересекаются» (общий кусок из 4
букв или определение называет другой ответ). Из годных цитат темы берутся 5 с разной длиной (от
короткой к длинной); первая тема начинается с цитаты ≤ 40 букв. Номера букв перемешиваются от seed
(seed = hash(masterSeed, 'words', slug, i)). Результат — `src/data/words.json`.
**Стабильность (append-only, §2.0):** id уровня «Слов» = sha1(`{ slug, quote }`) — правка
определений, переводов, словаря и порядок тем его не меняют. Прежний `src/data/words.json` —
список выпущенных уровней: они сохраняются в своей теме первыми, с теми же словами (если слова на
месте) и номерами букв; новые уровни дописываются в конец темы. Если выпущенный уровень пропал бы
(удалили его цитату), сборка падает; `--replace` — осознанно разрешить, `--fresh` — собрать с нуля.

**Формат уровня** (`src/data/words.json` → `{ meta, words: { campaign: [...] } }`):
```js
{ id /* sha1({slug, quote}) */, seed, chapter /* номер темы с 1 */, difficulty /* число букв цитаты */, slug, theme: { ru, en },
  quote, author, src, ru /* перевод цитаты */, clues: [{ w, p, c, ru }…],
  key: [26 чисел] /* key[буква A…Z] = номер 1…K или 0 */, given: 'ET' /* открытые буквы */ }
```
Инварианты (тесты): номера 1…K без пропусков и повторов; у каждой буквы цитаты и ответов есть
номер; каждая буква цитаты есть в ответах или открыта; у каждого ответа ≥ 2 неоткрытые буквы;
`id` = sha1({ slug, quote }). Данные вшиваются в сборку отдельным
`<script type="application/json" id="words">` (свой бюджет ≤ 350 КБ; «<» в JSON экранируется как
`\u003c`, §4.7); `readEmbeddedLevels` кладёт их в `levels.words`.

**Состояние и снимок.** Догадки хранятся по номерам (одна правда на номер — Lumin «one source of
truth»): `serialize` → `{ g: строка длины K ('.' — пусто), sel: [зона, k, i], cur, shown: [k…],
rev: [номер…], chk: [номер…], hints, hintUsed, ent, bad }`; `create(level, saved)` проверяет снимок,
открытые буквы всегда на месте. Перепечатка уже заполненного ответа идёт по его клеткам подряд.
`current` пишется, только если партия «тронута» (касание, клавиша, undo, сброс, подсказка) или
продолжена — просто открытый и закрытый уровень не затирает начатую партию (слот один, §3.3).

**Расширения контракта §5.1** (необязательные, остальные режимы их не задают):
`dom: true` + `view(root, api) → { update(state, info), destroy() }` — режим рисует себя
DOM-разметкой вместо холста, а тапы передаёт оболочке как `api.tap(target)` → `tap(state, target)
→ events`; `keyboard: true` + `key(state, key, t) → events` (key — 'A'…'Z', 'Backspace', 'Left',
'Right', 'Next'); `skin: 'lumin'` — оформление экрана игры, шторок, победы и списка уровней по
Lumin; `hintOptions(state) → [{ id, label, detail, disabled }]` + `hint(state, t, id)` — шторка
подсказок вместо двойного тапа; `campaignOnly`, `openByChapter`, `chapterTitle(chapter, level) →
{ru,en}`; `stats(state)` может вернуть `{ quote, accuracy, hints, vocab }` для экрана победы;
`titleFor(level, index, campaign) → {ru,en}` (заголовок экрана игры); `intro: [{title, text}]`
(знакомство при первом входе, `settings.introSeen`); результаты `hint(state, t, id)` —
`'cells'|'check'|'translate'|'none'`; события `miss` (неверная буква: лёгкая вибрация), `notice`
(`message:{ru}` — тост без штрафа), `select` (только выделение: пишется в current, не шаг undo) и
`complete` с `clue` и `message: {ru}` (тост; не показывается, если та же пачка событий решает
уровень). Физическая клавиатура (буквы, в т.ч. по `e.code` в русской раскладке; ⌫, ← →, Enter/Tab)
не перехватывается, пока открыт диалог (шторка, знакомство, подтверждение, победа) или фокус на
кнопке. Тосты без кнопок не перехватывают касания. VoiceOver: подписи клеток с номером, буквой и
состоянием, `aria-current` у выбранной, озвучка ввода (aria-live).
**Нативная оболочка** (App Store, Capacitor): `app.native` — нет карточки «На экран Домой», нет
Service Worker и отладочного `window.__roscherk`.

### 2.6 «Карандаш» (`draw`) — физические головоломки с рисованием
Пятый режим, добавлен 2026-10-15 по просьбе: «нарисовать что-то, чтобы шарик покатился; рой
насекомых атакует — нарисовать, чтобы защитить; уровни прямо сложные, с разным ландшафтом, с
дополнительными элементами вроде воздушных шаров». Это **рисование в мире с физикой**: всё, что
игрок рисует пальцем, становится твёрдым телом и живёт по законам физики.

**Движок.** 2D-физика — библиотека `matter-js` 0.20 (MIT, ~84 КБ в бандле; единственное
исключение из правила «без библиотек» §0: писать свою физику дороже и хуже). Мир — портретный
прямоугольник **W = 360 × H = 520** условных единиц (≈ CSS-px на iPhone), гравитация по умолчанию
(≈ 1000 ед/с²). **Фиксированный шаг** 1000/120 мс, два подшага на кадр 60 Гц; догон ≤ 4 кадров за
рендер (при большем — сим «замирает», а не ускоряется). Симуляция **детерминирована**: тот же
уровень + те же штрихи с теми же временами → тот же результат (все случайности — `mulberry32`
от seed уровня, `Matter.Common` не используется для случайного). Тела спят по умолчанию.

**Уровни** — рукописные JSON (`tools/draw/levels/<номер>-<slug>.json`), собираются в
`src/data/draw.json` (`npm run draw`), вшиваются в сборку отдельным `<script id="draw">`
(`levels.draw`, бюджет ≤ 250 КБ). Два типа:
- **«Шарик»** (`type:'ball'`): довести шарик до цели. Фаза **подготовки**: шарик заморожен,
  нарисованное падает и укладывается; кнопка **«Пуск»** отпускает шарик (`autoStart:true` —
  физика с первой секунды, для уровней на реакцию). **Победа** — центр шарика 30 шагов подряд
  внутри цели. **Проигрыш** —
  шарик упал за нижний край мира (y > H + 60) или коснулся шипов: событие `lost` с сообщением
  («Шарик упал» / «Шарик на шипах»), сим останавливается, в нижней панели — «Заново» (те же
  штрихи с нуля, снова подготовка) и «Сбросить».
- **«Рой»** (`type:'swarm'`): защитить банку мёда от роя. Фаза **подготовки**: насекомые ещё в
  гнёздах, физика идёт (нарисованное падает и укладывается), игрок строит защиту; кнопка
  **«Выпустить рой»** (основное действие нижней панели) начинает атаку; рисовать можно и во
  время атаки. **Победа** — прошло `time` секунд атаки, а банка цела. **Проигрыш** — насекомые
  коснулись банки `hp` раз (по умолчанию 1): «Мёд съеден».
- Смешанные уровни (`type:'ball'` + гнёзда): насекомые мешают шарику (толкают, облепляют);
  банки нет — проигрыш только по шарику.

**Рисование.** Палец ведёт штрих; точки — в единицах мира; штрих упрощается (минимальный отрезок
4 ед., Рамер–Дуглас–Пекер ε = 1,5) и на `up` становится **одним твёрдым телом**: составное из
прямоугольников-отрезков толщиной 6 и кругов в вершинах (`Body.create({ parts })`), плотность
0,0025, трение 0,7, упругость 0,05. По умолчанию штрихи **динамические** (падают, качаются,
толкаются); уровень может задать `ink.static:true` — штрихи приклеены к миру (обучение). Штрих
короче 6 ед. или из одной точки отбрасывается; штрих, пересекающий шарик/банку/насекомое
при создании, всё равно создаётся (тела разъедутся). **Чернила**: бюджет `ink.total` — суммарная
длина штрихов; остаток виден полосой над полем («Чернила 62 %»); когда чернил не хватает,
штрих обрезается по бюджету. **Звезда** — победа без подсказки и с расходом ≤ `ink.par`.

**Элементы уровня** (`items`), все координаты — единицы мира, y вниз:
- `terrain` — статичные полигоны/прямоугольники: `{ kind:'ground', poly:[[x,y]…] }` или
  `{ kind:'block', x,y,w,h, angle? }`; `ice:true` — трение 0,02 (лёд).
- `ball` `{x,y,r:12}`; `goal` `{x,y,r:18}` (сенсор-кольцо со звездой); `jar` `{x,y, hp:1, dynamic?:false}`
  (банка 30×36 на дне или на платформе; `dynamic:true` — её можно уронить/унести).
- `nest` `{x,y, insect:'wasp'|'beetle', count, every:400, delay:0}` — гнездо: выпускает `count`
  насекомых с интервалом `every` мс, начиная через `delay` мс после «Выпустить рой».
  **Оса** (r 5): без гравитации, сила к банке (к шарику на смешанных) + шум по seed, предел
  скорости 180 ед/с, толкает динамические штрихи (масса мала, но их много), застряв у преграды —
  скользит вдоль неё и ищет обход (сила вдоль касательной, смена знака раз в 0,7 с). **Жук**
  (r 6): гравитация, ползёт по земле к банке (горизонтальная сила), упёршись — подпрыгивает
  (импульс раз в 0,8 с), по наклону до 40° взбирается. Насекомое, коснувшееся шипов, гибнет.
- `balloon` `{x,y,r:9, lift:1.6, to?:indexItem, len?:60}` — воздушный шар: сила вверх `lift`×вес;
  `to` — привязан нитью (`Constraint`, длина `len`) к элементу (шарику, ящику, банке, доске):
  поднимает его; шар можно придавить нарисованным грузом или заслонить; касание шипов — лопается.
- `crate` `{x,y,w,h, density?}`, `plank` `{x,y,w,h:6,angle?}` — динамические; `seesaw` `{x,y,w}` —
  доска на оси; `fan` `{x,y,w,h, dir:[dx,dy], force}` — зона ветра (сила на все динамические тела
  внутри, анимированные линии); `spikes` `{x,y,w, dir:'up'|'down'|'left'|'right'}`.
- `ink` `{ total, par, static?:false }`, `time` (сек атаки, swarm), `seed`, `hint`/`tip` `{ru}`,
  `solution: [{ t: шаг, pts:[[x,y]…] }…]` — эталон: штрихи и шаги сима, на которых они появляются
  (для «Роя» до запуска — `t:0`; `launch: шаг` — когда эталон жмёт «Выпустить рой»).

**Проверка** (`tools/draw.mjs`, `npm run draw`, и тест): для каждого уровня в Node прогоняется
(1) эталон в темпе человека («Пуск» через 1 с после последнего штриха, когда всё улеглось) →
победа не позже `limit` − 5 с (по умолчанию `limit` 60 с), и тот же эталон со сдвигом на 1 с тоже
побеждает; (2) **без штрихов** (с запасом 25 % по времени) → победы нет, а в «Рое» банку съедают;
(3) длина эталона ≤ `ink.total`, `ink.par` ≥ длины эталона × 0,8 (звезда достижима);
(4) детерминизм — два прогона совпадают по позициям. Расхождение — ошибка сборки. Поля
`id` (sha1 содержимого без служебных), `chapter`, `difficulty` (= число штрихов эталона × 10 +
доля чернил × 10) дописывает сборщик.

**Кампания** — 60 уровней, 4 главы (окно из 3 открытых, как у линий): «Разминка» (1–8: рампы,
мостики, толкнуть; статичные чернила в 1–3), «Шарик» (9–24: пропасти, горки, лёд, качели,
вентиляторы, шары), «Рой» (25–44: осы, жуки, оба; банка на земле → на платформе → на шаре;
ветер сдувает защиту), «Буря» (45–60: смешанные: шарик под атакой, два гнезда, лёд + ветер +
шары). Сложность — не «спрятанная кнопка», а физика: мало чернил, насекомые с нескольких сторон,
преграды надо подпирать. Режим только в кампании (`campaignOnly`); `tip` на первых уровнях:
«Нарисуй мостик — линия станет твёрдой», «Чернила ограничены: смотри полосу сверху»,
«Жми „Выпустить рой“, когда защита готова».

**Экран** (Lumin): шапка — назад, «Карандаш · 7», справа у «Роя» — обратный отсчёт атаки
(`nextLabel`: «держись 12 с»); над полем — полоса чернил; поле — весь прямоугольник мира,
вписанный в холст (`layout`: масштаб, смещение); нижняя панель — отменить, сбросить, подсказка,
основное действие режима («Выпустить рой» / «Заново» после проигрыша), «Пропустить».
Рисование — **одним пальцем**, штрих виден сразу (чернильная линия 6 ед. с круглыми концами);
проигрыш — тост-сообщение и затемнение поля на 40 %. Отрисовка: терраин — `surface2` с контуром
ink 2 px (лёд — mist), штрихи — ink, шарик — лаванда с контуром ink, цель — пунктирное кольцо
sage со звездой, банка — янтарная (#D9A441 / #B98A2E) с крышкой ink, осы — тёмные овалы с
жёлтой полоской и крылышками (анимация по кадру), жуки — тёмные круги с лапками, шары — лаванда
с бликом и нитью, ящики — paper с контуром, вентилятор — стрелки и бегущие линии ветра, шипы —
треугольники ink. `prefers-reduced-motion` — без бликов и анимации крыльев (движение тел —
это игра, оно остаётся).

**Контракт.** `pointer`: `down` начинает штрих, `move` добавляет точки (гистерезис 2 ед., точки
округляются до 0,1 ед.), `up` создаёт тело (события `step` и `changed`; при обрезке по бюджету —
`notice` «Чернила кончились»). `serialize` → `{ strokes:[{t, pts}], steps, launched: шаг|null,
hintUsed }` — точки как есть; `create(level, saved)` восстанавливает мир **повтором** (штрихи
ставятся на своих шагах без повторного упрощения, прогон `steps` шагов, ≤ 36000 = 5 мин; дальше
штрихи переносятся на последний шаг, не теряются) — поэтому undo (снимок до штриха) и
продолжение партии точны. Повтор синхронный; замер в Node: ≤ 0,1 с даже для 5 минут подготовки
или полной атаки (повтор останавливается на победе/проигрыше, спящие тела дешёвые) — на телефоне
в 2–3 раза дольше, без заметного подвисания. Шар с подъёмной силой не засыпает (сила будит его
каждый шаг), поэтому «мир жив» для шаров считается по фактическому смещению за шаг. Упавшие в пропасть штрихи и ящики убираются из мира (чернила
потрачены, запись штриха остаётся). `render(ctx, state, layout, theme, t, opts)` сам продвигает сим по
реальному времени (`opts.now`), возвращает `true`, пока сим жив (тела не спят или идёт атака).
`reset` — мир заново, штрихи и чернила — тоже; `actions(state) → [{ id, label:{ru}, primary,
undoable }]` и `act(state, id, t) → events` — кнопки отдельной строкой над нижней панелью («Пуск»,
«Выпустить рой», «Заново»; строка зарезервирована, поле не прыгает; тосты поднимаются над ней).
`undoable:false` — действие не попадает в историю отмены: у «Карандаша» так у «Пуск» и «Заново»,
поэтому «Отменить» всегда убирает последний штрих и возвращает подготовку. `hint` — ghost
первого штриха эталона, которого ещё нет на поле (похожий штрих игрока: длина ±50 %, точки эталона
не дальше 15 ед. от его ломаной; лишние штрихи не мешают) (`kind:'ghost'`, пунктир 2,5 с; `hintUsed`);
`stats` — «Потрачено чернил: 62 %», «Штрихов: 3», «Выдержано: 20 с»; `perfect` — чернила ≤ par;
`footer` — «чернила 62 %». Расширения §5.1: `actions/act`, `continuous:true` (цикл рендера
не прерывается, пока `render` возвращает true — у физики это норма; бюджет кадра для dev —
8 мс), `worldRect:true` — layout по всему холсту (как `fullRect`).

### 3.2 Ежедневная и Бесконечность
- **Ежедневная**: один уровень в день; режим чередуется (zip → flow → stroke); берётся из
  подпула `daily` (40 уровней на режим, сложность главы 3, в «Бесконечность» не попадают).
  `dayNumber` = дни от 2026-01-01 по локальной дате `YYYY-MM-DD`; `mode = dayNumber % 3`;
  `index = FNV1a(date) % 40`. Хранить `daily: { streak, bestStreak, lastDate, history: [даты, ≤ 60] }`;
  серия растёт, если решён уровень за день, следующий после `lastDate`.
- **Бесконечность**: режим или «микс» (по умолчанию). Сложность растёт с серией: 0–4 → главы
  1–2, 5–9 → 3, 10–14 → 4, 15+ → 5 (по `chapter` уровня пула; уровень выбирается случайно
  среди непройденных в этой сессии). Серия обрывается подсказкой или пропуском; выход
  сохраняет серию через `current`. «Пропустить» всегда доступна. `endless: { best: {zip, flow, stroke, mix} }`.

### 3.3 Хранилище (`localStorage`, ключ `roscherk.v1`)
```js
{
  v: 1,
  progress: { zip: { [levelId]: { star: bool, bestMs: number } }, flow: {…}, stroke: {…} },
  skipped:  { zip: [levelId…], flow: […], stroke: […] },
  current:  { kind:'campaign'|'daily'|'endless', mode, levelId, elapsedMs, hintUsed, resets,
              startedAt, state: serialize(state), endless?: { streak, modeChoice } } | null,
  settings: { sound: true, theme: 'system'|'dark'|'light', flowNumbers: false, installCardClosed: false, installReminderShown: false, introSeen: [] },
  // progress, skipped и endless.best — по id режима, включая 'words' (§2.5)
  daily:    { streak, bestStreak, lastDate, history: [] },
  endless:  { best: { zip:0, flow:0, stroke:0, mix:0 } },
}
```
`current` записывается на каждый `up`, `undo`, `reset`, `hint` и на `visibilitychange→hidden`
/ `pagehide` (`beforeunload` на iOS не используется); при открытии того же уровня дорожка,
таймер и `hintUsed` восстанавливаются; победа очищает `current`. Прогресс пишется синхронно
сразу после победы. Все чтения/записи — в try/catch; при битом JSON — чистое состояние.
Таймер уровня — сумма активных интервалов: на `hidden` интервал закрывается, на `visible`
открывается новый; анимации на возврате стартуют от `performance.now()`.

### 4.2 Трассировка свайпа (`src/core/grid.js`)
Отрезок между предыдущей и текущей позицией указателя трассируется supercover-алгоритмом
(Amanatides–Woo) в **4-связную** последовательность клеток. При прохождении через угол
промежуточная клетка выбирается из двух ортогональных: берётся легальная по правилам режима
(колбэк `canStep(from, to)`); если легальны обе — та, чей центр ближе к отрезку. Каждый
промежуточный шаг проверяется правилами режима; на первом нелегальном шаге обработка
останавливается на последней легальной клетке (без телепортации), и дорожка не растёт, пока
палец не вернётся в клетку, соседнюю с головой. **Гистерезис**: клетка считается
«достигнутой», когда указатель в её центральных 70 % по каждой оси; укорочение — только при
движении. Всё это — чистые функции без DOM, покрытые тестами.

### 4.3 Canvas, рендер, производительность
- `devicePixelRatio`; layout пересчитывается через `ResizeObserver` на контейнере и
  `matchMedia('(resolution: …)')`; `layout()` — чистая функция без мутации state; активный
  указатель продолжает работать с новым layout. Оболочка передаёт в `layout()` не весь холст, а
  прямоугольник, поднятый к его верху (`boardRect`: верх квадрата поля ≈ 22 % свободной высоты,
  не меньше 12px и не ниже центра), чтобы оверлей победы не закрывал поле целиком.
- **Рендер по запросу**: оболочка ставит dirty-флаг при любом изменении state/указателя → rAF;
  цикл длится, пока `render` возвращает `true` (идёт анимация). Нет постоянного цикла.
- **Статический слой** (сетка, стены, числа, точки, узлы) — offscreen-canvas, перерисовывается
  только при смене уровня, темы или размера; на кадре — только дорожки, подсказка, анимации.
  Режим хранит кэш в несериализуемом поле `state._cache`.
- Свечение линии — вторая, более широкая обводка с низкой альфой под основной. **`shadowBlur`
  запрещён.** Цвета темы читаются из CSS-переменных один раз при смене темы в объект `theme`.
- Бюджет: ≤ 4 мс на кадр при рисовании (dev-режим измеряет `performance.now()` и пишет в консоль
  при превышении; первые 3 кадра после смены уровня, темы или размера не считаются — там строится
  статический слой и играет всплытие).
- Анимации: появление уровня (всплытие 200 мс), линия с круглыми концами, вспышка клетки/узла
  при `step`, вспышка стены/чужой дорожки/отрезка при `reject`/`cut`, победа — мягкое радиальное
  свечение цвета режима ≤ 700 мс (Lumin: без конфетти), затем оверлей. При
  `prefers-reduced-motion: reduce` — без свечения, пульса и всплытия; мгновенное закрашивание
  остаётся.

**Дизайн-система Lumin для всего приложения** (2026-10-15, `~/Downloads/lumin-word-design-system`):


### 4.5 Звук
`audio.js`: `AudioContext` создаётся лениво внутри первого `pointerdown`; на каждом
`pointerdown` и `visibilitychange→visible`, если `ctx.state !== 'running'` — `resume()`.
Синтез без файлов: «тик» при `step` (тон слегка растёт с длиной дорожки), «отказ», «complete»
(flow), аккорд победы. Вибрация — `navigator.vibrate?.()` под guard. Каждый шаг/отказ имеет
визуальный отклик независимо от звука.

### 4.6 Service Worker, манифест, иконки
- `sw.js`: на `install` прекэширует `./`, `index.html`, манифест, иконки; cache-first; имя кэша
  `'roscherk-' + contentHash` (подставляет build.mjs); старые кэши удаляются на `activate`;
  `skipWaiting` + `clients.claim`; `registration.update()` на `visibilitychange→visible`; при
  `updatefound` — тост «Доступно обновление → Перезапустить» без автозакрытия, с кнопкой
  «закрыть» (закрываемый). На `localhost` SW не регистрируется.
- `manifest.webmanifest`: `name: Росчерк`, `short_name: Росчерк`, `display: standalone`,
  `start_url: ./`, `scope: ./`, `orientation: portrait`, `background_color`/`theme_color` = фон
  тёмной темы, иконки 180/512.
- `icon-180.png`: непрозрачный фон во всю площадь, **без собственных закруглений**, один
  крупный символ (росчерк-линия) с полями ≥ 10 %. Источник — `assets/icon.svg`; растеризация
  `tools/icon.mjs` через `qlmanage -t -s 1024` + `sips` (есть на этом Mac), fallback — Pillow.

### 4.7 Сборка (`tools/build.mjs`)
esbuild: `bundle`, `format:'iife'`, `target:['safari15']`, `minify`, `charset:'utf8'`;
CSS инлайн в `<style>`; бандл инлайн в `<script>` с заменой `</script` → `<\/script`;
`levels.json` — отдельный `<script type="application/json" id="levels">` и `JSON.parse`;
`contentHash` — sha1 **всего содержимого поставки** (бандл, CSS, `levels.json`, шаблон
`index.html`, `sw.js`, манифест; части хэшируются с именем и длиной), а не только бандла: любое
изменение релиза меняет имя кэша SW. Подставляется в `sw.js`, в настройки (версия) и в `index.html`.
Проверки: `dist/index.html` ≤ 1 МБ, `levels.json` ≤ 400 КБ (иначе компактное кодирование:
zip `path` — строка направлений `RDLU`, flow — строка индексов цветов длиной n²).

## 5. Контракты

### 5.1 Модуль режима `src/modes/<id>.js`
```js
export default {
  id: 'zip',
  icon: 'route',                          // имя иконки режима из dom.js (карточка на главном); карты id→иконка в оболочке нет
  name: { ru: 'Маршрут', en: 'Route' },
  tagline: { ru: 'Одна дорожка через все клетки', en: '…' },
  helpText: { ru: '…', en: '…' },
  color: '#4F8CFF',                       // акцент режима (тёмная тема); colorLight — для светлой
  colorLight: '#2F6FE0',
  create(levelData, saved /* результат serialize или undefined */) → state,   // чистая
  serialize(state) → plainObject,         // JSON-сериализуемый снимок партии (без _cache)
  layout(state, rect /* {x,y,w,h} CSS-px холста */, theme) → layout,          // чистая
  render(ctx, state, layout, theme, t /* performance.now() */, opts /* {reducedMotion, flowNumbers, appeared} */) → boolean, // true = нужен ещё кадр; appeared:true — состояние после undo/restore, всплытие появления не играть (§4.3)
  pointer(state, layout, ev /* {type:'down'|'move'|'up'|'cancel', x, y, t} */) → events[],
  isSolved(state) → boolean,
  reset(state) → void,                    // очищает поле (flow — и счётчик ходов, §2.3), не трогает hintUsed/статистику попытки (тупики stroke)
  hint(state, t) → { kind:'cells'|'edge'|'flow'|'start'|'rollback'|'none', … },  // ставит state.hint={…,until:t+2500}, state.hintUsed=true; при kind:'none' (поле решено / лимит узлов) hintUsed НЕ ставится
  truncate?(state, hint, t) → boolean,    // необязательно (zip): кнопка «Укоротить до неё» для hint kind:'rollback' ({cell, keep, label}); false — подсказка устарела (клетка hint.cell уже не на позиции hint.keep)
  stats(state) → { lines: [{ru,en}…] },   // строки для оверлея победы («Возвратов: 3», «Ходов 7 / 6»)
  perfect(state) → boolean,               // flow: ходов == потоков; остальные — true
  ghost(levelData, layout) → [{x,y}…] | null, // точки первых 3–4 шагов решения в CSS-px холста по layout (для обучения); без layout — в единицах сетки/решётки; иначе null
  nextLabel(state) → string|null,         // zip: «следующая: 4»; остальные null
  footer(state) → {ru,en}|null,           // flow: «ходов 5 · 83 %» (процент — клетки дорожек длины ≥ 2)
}
```
События `pointer()`: `{kind:'step'}`, `{kind:'reject', reason, cell?|edge?}`, `{kind:'cut'}`,
`{kind:'complete'}`, `{kind:'deadend', startMatters}` (stroke; `startMatters:false` — выбор старта
не важен, см. 2.1), `{kind:'solved'}` (ровно один раз, когда
isSolved стал true), `{kind:'changed'}` (любое изменение состояния — оболочка ставит dirty и
пишет снимки). Режим сам не трогает DOM, звук, хранилище.

### 5.2 Генератор `src/modes/<id>.gen.js`
```js
export const CHAPTERS = [ { chapter:1, from:1, to:6, minDifficulty:1, …параметры режима… }, … ];
export const POOL   = [ { chapter:1, count:30, …}, … ];      // 150 уровней пула, по главам
export const DAILY  = { chapter:3, count:40, … };
export function generate(seed /* uint32 */, spec /* элемент CHAPTERS/POOL/DAILY */, levelIndex /* номер уровня кампании с 1 (CHAPTERS) или порядковый номер в наборе с 1 (POOL/DAILY) */) → levelData | null;
export function tipFor(levelData, levelIndex /* с 1 */, prevLevels) → {ru}|undefined;   // обязательные tip из 3.1
export function profile(spec, levelIndex) → string|number;  // необязательно: профиль слота кривой — фичи, включаемые по номеру
//   уровня (zip: 'base' / 'no-walls' / 'walls' / 'marks'; stroke: эффективный номер уровня; flow: 'any').
//   tools/generate.mjs ставит кандидата только в слот с тем же профилем; без экспорта слоты спека взаимозаменяемы
//   (генератор печатает предупреждение).
// Необязательно: MAX_NODES — лимит узлов солвера для generate/verify; allowNonUnique(spec) → bool —
// уникальность best effort с полем unique (flow 9×9); UNIQUE_REQUIRED = false — уникальность не требуется (stroke).
```
Генератор детерминирован от `seed` (использует только `src/core/rng.js`). `null` — затравка
отвергнута (лимиты, фильтры). `levelData` без служебных полей; `id/seed/chapter/difficulty/tip`
дописывает `tools/generate.mjs`.

### 5.3 Солвер `src/modes/<id>.solve.js`
```js
export function solve(levelData, { maxNodes, maxSolutions = 2 }) → { solutions: [...], nodes, difficulty, complete: boolean };
export function validate(levelData, solution) → boolean;       // решение корректно по правилам
export function solutionOf(levelData) → solution;               // эталон из данных
```

### 5.4 Форматы данных уровней (`src/data/levels.json`)
```js
{ meta: { masterSeed, generatedAt, version }, zip: { campaign:[…], pool:[…], daily:[…] }, flow: {…}, stroke: {…} }
// zip:    { id, seed, chapter, difficulty, tip?, n, path:[cellIdx…] /* решение, r*n+c */, marks:[[cellIdx, number]…], walls:[[a,b]…] /* a<b, ортогональные соседи */ }
// flow:   { id, seed, chapter, difficulty, tip?, unique, n, flows:[[cellIdx…]…] /* решение; цвет = индекс потока */ }
// stroke: { id, seed, chapter, difficulty, tip?, w, h, nodes:[[x,y]…] /* (столбец, строка) с джиттером, в единицах решётки */, edges:[[a,b,dir]…] /* dir 0 — любое, 1 — только a→b */, start: nodeIdx|null, closed: bool, solution:[nodeIdx…] }
```

### 5.5 `tools/generate.mjs`
Для каждого режима и набора (campaign/pool/daily): для каждого chapter-спека генерирует
кандидатов (seed = hash(masterSeed, mode, kind, chapter, attempt)) **для слота**
`levelIndex = firstIndex + attempt % need` (кандидат помечается профилем своего слота,
`profile(spec, levelIndex)`), решает солвером, отбрасывает `difficulty < minDifficulty`,
невалидные, неуникальные (где требуется) и дубликаты по `id`, набирает ≥ 2× нужного числа и
раздаёт кандидатов **по слотам**: в слот попадает только кандидат его профиля, `difficulty` по
слотам главы не убывает, соседи отличаются ≤ 2× (старт — от медианы профиля первого слота, а не
от самых лёгких). Если такого набора нет — генерирует ещё кандидатов, и так до потолка попыток
(`need × 60`); после потолка — ближайший по сложности с предупреждением. Присваивает `id`, `tip`.
Пишет `src/data/levels.json` и печатает статистику (размеры, difficulty по главам, число
попыток, время). `tools/verify.mjs` (`npm run verify`): перепроверяет все уровни —
валидность решения, уникальность (zip, flow ≤ 8), пересчёт difficulty, расхождения — ошибка.

### 5.6 Общие ядровые модули (`src/core/`)
- `rng.js`: `mulberry32(seed)` → `{ next() ∈ [0,1), int(n), pick(arr), shuffle(arr) }`; `hash32(...parts)` (FNV-1a по строкам/числам).
- `grid.js`: `traceCells(from:{x,y}, to:{x,y}, cell /* размер */, origin, n, canStep(a,b)) → [cellIdx…]`; `cellAt(x,y,layout,hysteresis)`; `neighbors(idx,n)`; `areAdjacent(a,b,n)`.
- `hash.js`: `contentId(obj) → 8 hex` (sha1 в Node; в браузере не нужен).
- `storage.js`, `audio.js`, `theme.js`, `i18n.js`, `canvas.js` (DPR, ResizeObserver), `input.js` (один указатель, capture, cancel→up),
  `anim.js` (easing, таймлайны), `particles.js` (конфетти; с Lumin не используется), `daily.js`, `endless.js`, `progress.js` (попытка, звезда, окно уровней, пропуск).

## 7. Тесты (`npm test`, секунды)
1. Каждый солвер сравнивается с наивным перебором без отсечений на случайных задачах ≤ 5×5
   (zip, flow) / ≤ 10 рёбер (stroke) — равенство числа решений (главный тест корректности отсечений).
2. Рукописные задачи с 0/1/2/3 решениями для каждого режима.
3. Детерминизм: генерация фиксированной выборки (2 уровня на главу на режим) при фиксированном
   seed совпадает с коммитнутым хэшем.
4. Чистые тесты ввода без DOM: трассировка свайпа со стенами и через угол, гистерезис,
   укорочение, обрезка чужого потока, второй указатель игнорируется, порядок узлов stroke,
   отказ при входе в K, терминальность K, стрелки, closed.
5. Валидность всех уровней `levels.json` по сохранённому решению; размер `dist/index.html` ≤ 1 МБ.
6. Рендер — smoke: `render` на фейковом ctx (Proxy, записывающий вызовы) не бросает и не
   использует `shadowBlur`.
Полное доказательство уникальности и пересчёт `difficulty` — `npm run verify` (минуты).

## 8. Критерии приёмки
- `npm test` зелёный; `npm run verify` без расхождений; `npm run build` без ошибок, ≤ 1 МБ.
- 100 + 150 + 40 уровней на режим; `difficulty` каждого ≥ порога главы и не убывает внутри главы.
- Эмуляция iPhone 390×844 и 375×667: рисование без «перескоков» при быстром свайпе, сквозь
  стены нельзя, второй палец ничего не меняет, нет скролла/зума страницы, кнопки ≥ 44pt,
  тёмная/светлая темы читаемы, 9×9 с 12 потоками различимо.
- Незавершённая партия переживает перезагрузку страницы; прогресс — тоже.
- Каждый режим и оболочка прошли ревью пары «архитектор + критик»; блокеры и major закрыты.
- Установка с опубликованного URL на домашний экран, запуск в standalone, второй запуск
  в авиарежиме открывается (проверяет пользователь на своём iPhone — у нас нет устройства).
