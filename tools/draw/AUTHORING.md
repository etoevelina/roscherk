# Как делать уровни «Карандаша»

Файл уровня — `tools/draw/levels/NN-slug.json` (NN — номер 01…60, slug — латиницей). Формат и
правила — `docs/SPEC.md` §2.6. Проверка одного уровня: `node tools/draw.mjs --only NN`
(эталон должен побеждать, бездействие — нет, чернил хватает, звезда достижима). Трассировка
эталона по полсекунды: `node tools/draw.mjs --trace NN` (положение шарика/банки, фаза, число
насекомых). Сборка всех: `node tools/draw.mjs` → `src/data/draw.json`.

## Мир
- Прямоугольник 360 × 520, **y растёт вниз**, (0,0) — левый верх. Слева и справа невидимые
  стены; снизу — пропасть (шарик ниже 580 — проигрыш), сверху открыто.
- Гравитация ≈ 1000 ед/с²: падение с высоты 200 занимает ~0,6 с. Шарик r=12, катится живо
  (почти без потерь), по ровному проезжает далеко. Прыгает с небольших ступенек.
- Единицы и «ощущение»: 1 ед ≈ 1 CSS-px на iPhone; палец рисует штрих толщиной 6.

## Элементы (`items`, массив; индексы нужны для `balloon.to`)
| kind | поля | заметки |
| --- | --- | --- |
| `ground` | `poly:[[x,y]…]`, `ice?` | статичный простой полигон (без самопересечений), любой формы: склоны, холмы, ямы; `ice:true` — скользкий |
| `block` | `x,y,w,h, angle?, ice?` | статичный прямоугольник, (x,y) — левый верх |
| `ball` | `x,y` | шарик (один); на «Шарике» заморожен до «Пуск» |
| `goal` | `x,y, r?:18` | цель-кольцо; победа — центр шарика внутри 0,25 с |
| `jar` | `x,y, hp?:1, dynamic?` | банка мёда 30×36 (x,y — центр); статична, пока `dynamic:true` |
| `nest` | `x,y, insect:'wasp'|'beetle', count, every?:400, delay?:0` | гнездо: `count` насекомых с интервалом `every` мс через `delay` мс после запуска |
| `balloon` | `x,y, lift?:1.6, to?:idx, len?:60` | шар: тянет вверх силой `lift` × вес шарика; `to` — нить к элементу с индексом idx (ящик, доска, банка `dynamic`, шарик) |
| `crate` | `x,y,w,h, density?` | ящик (x,y — центр), динамический |
| `plank` | `x,y,w,h?:6, angle?` | доска, динамическая |
| `seesaw` | `x,y,w?:120` | доска на оси в (x,y) |
| `fan` | `x,y,w,h, dir:[dx,dy], force?:0.8` | зона ветра (x,y — левый верх): сила `force` × вес на всё динамическое внутри |
| `spikes` | `x,y,w, dir:'up'|'down'|'left'|'right'` | шипы (x,y — левый верх полосы длиной w, толщина 10): насекомые гибнут, шар лопается, шарик — проигрыш |

Поля уровня: `type:'ball'|'swarm'`, `seed` (целое), `ink:{ total, par, static? }`,
`time` (сек атаки, обязательно для swarm; обычно 12–25), `tip:{ru}` (совет под полем, только
если он нужен), `autoStart:true` (физика без «Пуск»: уровни на реакцию), `limit` (сек на эталон,
по умолчанию 60), `solution:[{ t, pts:[[x,y]…] }…]`, `launch` (шаг «Пуск»/«Выпустить рой» в
эталоне; без него — сразу после последнего штриха эталона; 120 шагов = 1 с).

## Как ведут себя насекомые
- **Оса** (r 5, летает): тянется к банке (или к шарику, если банки нет) с лёгким дрожанием,
  скорость до 180 ед/с, толкает нарисованное (массой), застряв у преграды — ползёт вдоль неё
  и ищет обход. Полностью закрытый купол держит ос; щель шире ~12 ед — пролезут.
- **Жук** (r 6, ползёт): по земле к банке, упёрся — прыгает (высота ~85 ед), наклон до ~40°
  берёт. Пролезает под мостиками, перелезает низкие заборы.
- Укус банки = насекомое исчезает, `hp` −1. `hp` по умолчанию 1: один укус — проигрыш.

## Чернила и штрихи
- Штрих — ломаная; по умолчанию **динамический** (падает, ложится, качается, его можно
  сбить). Чтобы мостик держался, его концы должны лежать на опорах; длинный пролёт провисает
  и может соскользнуть. Груз над шариком — толчок. Замкнутая «чашка» вокруг банки — купол.
- `ink.static:true` — штрихи приклеены к миру (только главы 1–2 для обучения).
- `ink.total` — бюджет длины; `ink.par` — порог звезды. Правила: **par ≥ 0,8 × длина
  эталона** (иначе звезда недостижима) и par ≤ total. Сложность — через скупой бюджет:
  total ≈ 1,1–1,4 × длина эталона на сложных уровнях, par ≈ 0,85–1,0 × длина эталона.

## Эталон (`solution`)
- Проверка играет эталон **в темпе человека**: «Пуск» нажимается через 1 с после последнего
  штриха, когда нарисованное улеглось (не позже 5 с). Затем тот же эталон прогоняется ещё раз
  со сдвигом на 1 с — он тоже должен победить: решение не может зависеть от точного шага.
  На `autoStart` первый штрих не раньше шага 60, между штрихами ≥ 90 шагов.
- Бездействие проверяется с запасом 25 % по времени; для «Роя» без защиты банку обязаны съесть.
- Эталон должен побеждать не впритык: минимум за 5 с до `limit`.
- `tip`, `hint`, `limit` не входят в id уровня — их можно править после релиза без потери
  прогресса игроков; всё остальное (items, ink, seed, solution, time, launch, autoStart) — новый id.
- Штрихи в порядке рисования; `t` — шаг, на котором штрих появляется (0 — в подготовке).
  Пусть эталон не тоньше реального пальца: 4–12 точек на штрих, отрезки ≥ 4 ед.
- «Пуск»/«Выпустить рой» — на шаге `launch` или сразу после последнего штриха.
- Эталон должен быть **честным**: такой штрих может нарисовать человек пальцем за 1–2 с.
- Полезно: `--trace NN` показывает, где шарик через каждые 0,5 с.

## Требования к уровням
- Разный ландшафт (склоны, ямы, башни, лёд, навесы) — не одна и та же полка.
- Сложность растёт: в главе «Разминка» решение очевидно, в «Буре» нужно 3–5 штрихов,
  скупые чернила, несколько угроз сразу.
- Каждый уровень вводит или сочетает механики, а не повторяет предыдущий.
- Бездействие **не должно** приводить к победе (проверка это ловит).
- Без текста-подсказки решения в `tip`; tip — только на первых уровнях механики.
